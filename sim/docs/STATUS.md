# 재현 무대 상태 (단계마다 갱신)

## 확인 방법 (2026-11-14)
- `npm run check`(타입) 통과, `npm test`(연결기 자체 검사 18요청·33행, 가짜 fetch로 동시 PUT 상한·최신 값·낡은 GET·끊기 세대, 깜빡이 우선) 통과.

## 실측으로 알게 된 것 (Virtual Console)
- 하트비트 `POST /browser/session?client=…`만으로 `bridge_ready`가 true가 된다. 콘솔 페이지를 브라우저로 열 필요 없다.
- `lights.hazard_on`은 **램프 점멸 순간**을 그대로 보여 준다(0.5초마다 true/false). 텔레메트리는 최근 1.5초 안에 true면 켜짐으로 본다.
- 비상등과 방향지시등은 서로를 끈다(방향지시 쓰면 비상등 false). 연결기는 비상등이 켜져 있으면 비상등만 보낸다.
- `/vehicle/body` 한 번에 `door_fl… window_fl… trunk frunk doors_locked ambient_color ambient_brightness`를 같이 보낼 수 있다(200).
- 텔레메트리 `/vehicle/telltales/simulator?type=ABS&state=On&color=Red` → `telltales.actual.ABS.state`.
- 맥 부하가 높을 때(load 30 이상) PUT 왕복이 0.8~3.5초까지 늘었다. load 60~90일 때는 브라우저 PUT이 4초 제한에 걸려 실패하기도 했다(curl은 같은 때 30ms). 연결기는 동시 2개까지 보내고, 하트비트 3번 연속 실패해야 끊김으로 본다.

## 안 된 것 / 한계
- 외곽선(깊이 1px)·상자 모서리 베벨: 아직 없음 (아트 디렉션 2절).
- 차는 블록 형태의 일반형. 문 열고 타는 동작·손 흔들기 같은 사람 동작 없음(걷기는 위아래 흔들림만).
- 충돌 처리 없음: 주인공 차는 연석 안쪽으로만 묶이고, 지나가는 차와 겹칠 수 있다. 무대 끝(±50m)에서 반대편으로 돌아온다.
- 주인 선출은 Web Locks라 보안 컨텍스트(localhost·https)에서만 된다. LAN IP http로 열면 예전처럼 `?view=` 없는 창이 모두 주인이다.
- 지나가는 차·보행자는 창마다 따로 계산한다(새 창에서 위치가 조금 다를 수 있음). 주인공 차는 공유.
- 텔레메트리의 "앱이 읽은 값" 칸은 없다. 지금은 에뮬레이터(Virtual Console) 값까지. 앱이 값을 내보내는 길(설계 12절, `adb reverse`)이 생기면 칸을 더한다.
- 공조·좌석 위치·배터리·와이퍼 등 44개 기능은 상태 키가 없다 (매핑표 "아직 없음").
- Chrome 실브라우저로는 안 봤다(Playwright Chromium 헤드리스만). 60fps 측정 안 함.
