# eval-design: 검증 설계

## 먼저 읽기
`prd-spec` 추적 표, `risk-compliance` 리스크 표, `JUDGE_DEMO.md`

## 순서
1. 무엇을 증명할지 정한다(심사 4항목 중 어디의 증거인가).
2. 기능마다 골든 케이스: Virtual Console에서 바꿀 값 → 앱이 보여야 할 것·하면 안 되는 것.
3. 주행 중 안전 사례는 꼭 넣는다: 주행 상태 불명 → 주행 중 취급, 주행 중 긴 글·입력창이 안 뜸, 음성이 외부로 안 나감.
4. 통과/경고/실패 기준을 숫자나 관찰로 정한다. "정확도"는 정의 없이 쓰지 않는다.
5. 앱 안에 AI·추천 같은 가변 출력이 있으면 반드시 넣어야 할 것·넣으면 안 되는 것을 적는다.
6. 언제 다시 돌릴지: 기능 추가 때, 시연 영상 녹화 전, 2차 PT 전.

위험 사례에 fail-closed 사례가 있다 · 다른 팀원이 표만 보고 다시 돌릴 수 있다.
