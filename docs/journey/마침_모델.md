# 마침 모델: 묻지 않고 닫는 법

작성 날짜: 2026-11-15 · 코드: [`core/.../EndingPolicy.kt`](../../core/src/main/kotlin/com/mangsang/app/core/EndingPolicy.kt) · 테스트: [`EndingPolicyTest.kt`](../../core/src/test/kotlin/com/mangsang/app/core/EndingPolicyTest.kt) · 재생용 값: [`sim/journey/scenarios.json`](../../sim/journey/scenarios.json) · 여정: [여정_초정밀.md](여정_초정밀.md)

근거 파일 경로(`10_research/...`)는 팀 비공개 리서치 저장소 기준이고, 논문·문서 이름은 함께 적었다. 표시: [근거]는 출처가 있는 값, [가정]은 우리가 정한 초깃값(실사용 로그로 다시 맞출 값), [SDK 확인 필요]는 Pleos 에뮬레이터·실차에서 아직 읽어 보지 못한 신호.

## 1. 문제 정의

기도나 조용한 머묾의 끝을 사용자에게 묻는 순간, 그 질문이 머묾을 깬다. "마치겠습니까?"는 대답을 요구하고, 대답하려면 눈을 뜨고 화면을 읽어야 한다. 반대로 타이머가 정확히 15분에 "끝"을 선언하면 아직 기도 중인 사람을 자른다.

룸19는 다르게 한다.

1. **끝을 묻지 않는다.** 사용자가 끝날 준비가 된 정도를 확률 p로 추정한다.
2. **문을 한 번에 닫지 않고 조금씩 연다.** p가 오르면 빛이 아주 천천히 밝아지고(되돌릴 수 있음), 더 오르면 배경음이 물러나고, 충분히 확실할 때만 한 문장을 말한다.
3. **버튼은 숨기지 않되, 누르지 않아도 되게.** 화면 구석의 작은 "마치기"는 항상 있다. 이 버튼을 누른 비율이 낮을수록 모델이 잘 맞힌 것이다.
4. **일찍 끊는 실수가 늦게 끊는 실수보다 비싸다.** 기도 중인 사람을 깨우는 비용이 1~2분 더 앉아 있게 하는 비용보다 크다는 비대칭을 문턱에 넣는다.

근거 맥락
- 끝 경험이 전체 기억을 바꾼다: 끝을 덜 괴롭게 늘린 군이 경험 전체를 덜 나쁘게 기억(Redelmeier 2003, n=682) [근거: `10_research/domain/2026-11-15_차안의식_리서치/D3_심리_생리_근거/02_심리생리_근거.md` 1절 "전환"].
- 향심기도는 끝나면 눈 감은 채 약 2분 머문 뒤 나온다 [근거: `D1_종교와_의례/01_의식행위_종교별.md` 1-1]. 끝은 "선언"이 아니라 "여운"이다.
- 끝은 "원위치 + 같은 신호 + 안전 확인"의 세트(안마의자 Auto Restore, 죽비 세 번 방선) [근거: `D7_우수UX_사례/00_사례와_교집합.md` 1절, `D8_경험설계_재현/05_경험설계_재현.md` 1.2].

## 2. 모델

### 2.1 상태

사람의 상태를 둘로 둔다: **머묾(S0)** 과 **준비됨(S1)**. 준비됨은 흡수 상태다(한 번 끝낼 마음이 들면, 반대 증거가 오기 전까지는 그대로). 준비되는 시각을 확률변수 R(초, 세션 시작 기준)로 본다.

p(t) = P(R ≤ t | 지금까지의 신호) 를 매 초 갱신한다.

### 2.2 사전분포: 로그정규 + 맥락 + 개인 잔차

ln R ~ Normal(μ, σ²)

μ = ln b(맥락) + δ

- **기준 시각 b** [가정]
  - b = max(60, 의향초 - 90) × exp(0.10 × ln(운전분 / 30) + 심야보정)
  - 의향초: 사용자가 고른 길이(또는 "12시 28분까지"처럼 정한 시각에서 계산). 90초를 빼는 이유: 의향은 돌아옴(90초)까지 포함한 전체 길이이고, R은 "돌아옴을 시작해도 되는 시각"이다 [근거: 돌아옴 60~90초, `05_경험설계_재현.md` 2.2].
  - 운전 시간 탄력 0.10: 오래 운전한 날일수록 일과 떼어내기(detachment)에 시간이 조금 더 든다는 가정 [가정, 방향 근거: Sonnentag & Fritz 2007, `02_심리생리_근거.md` 2.7]. 40분 운전이면 +2.9%, 12분이면 -8.8%.
  - 심야보정: 22~05시 -10%. 졸음 위험 때문에 늦은 밤엔 조금 일찍 연다 [가정, 방향 근거: 30분 낮잠 뒤 수행 저하 최대 45분(Hilditch 2016), `02_심리생리_근거.md` 1절 "출발 전 안전"].
- **개인 잔차 δ** 는 정규-역감마 NIG(m, κ, α, β)로 둔다(5절). 처음엔 m=0.
- **σ** 는 NIG의 예측분포 척도 √(β(κ+1)/(ακ)). 초깃값 0.18 [가정]: 사용자가 직접 고른 길이라 흩어짐이 작다고 본다. 15분 의향에서 "준비" 80% 구간이 약 11.0~17.5분.

왜 로그정규인가: 세션 길이는 음수가 없고 오른쪽 꼬리가 길다(조금 더 머무는 날은 있어도, 시작하자마자 끝내는 날은 드물다). 로그정규는 공액 갱신이 단순하다(로그를 취하면 정규).

### 2.3 시간 갱신식 (해저드)

로그정규 누적분포 F(t) = Φ((ln t - μ) / σ) 의 이산 해저드:

```
h_k = (F(t_k) - F(t_{k-1})) / (1 - F(t_{k-1}))
p_k⁻ = p_{k-1} + (1 - p_{k-1}) · h_k
```

연속형으로 쓰면 dp/dt = (1 - p) · λ(t), λ(t) = f(t) / (1 - F(t)).

성질: 신호가 하나도 없으면 p(t) = F(t)와 정확히 같다(테스트 `withoutSignalsPEqualsLognormalCdf`).

### 2.4 관측 갱신식 (우도비)

신호 s가 오면 오즈에 우도비를 곱한다:

```
odds_k = p_k⁻ / (1 - p_k⁻) · LR(s)
p_k   = odds_k / (1 + odds_k)
```

LR(s) = P(s | 준비됨) / P(s | 머묾). 이 곱셈은 **사전 p가 작을 때 거의 아무 일도 하지 않는다.** 세션 2분째에 안전벨트를 세 번 매고 화면을 만져도 p는 0.000에 머문다(테스트 `earlySignalsCannotEndSession`). 이것이 의도다: 초반의 움직임은 "자리 잡기"이지 "끝내기"가 아니다.

## 3. 결정 규칙

### 3.1 비대칭 비용에서 문턱으로

행동 a(빛 올리기, 배경음 줄이기, 말하기)를 지금 할지 정한다. 아직 머묾인데 행동하면 비용 c_e(a), 이미 준비됐는데 안 하면 비용 c_l = 1.

- 행동의 기대 비용 = (1 - p) · c_e(a)
- 기다림의 기대 비용 = p · c_l

따라서 **p > c_e / (c_e + c_l)** 일 때 행동한다.

| 단계 | 출력 | c_e (늦음=1 대비) [가정] | 문턱 p* | 되돌릴 수 있나 |
|---|---|---|---|---|
| 빛 올림 | 앰비언트 +2%/분 | 1 | 0.50 | 쉽다. 2%/분은 눈치채기 어려운 속도 |
| 소리 물림 | 배경음 -1dB/5초 페이드 시작 | 7/3 | 0.70 | 중간. 사라진 소리는 사람이 알아챈다 |
| 마침 문장 | TTS "이제 천천히 돌아올게요." 1회 | 17/3 | 0.85 | 어렵다. 말은 거둘 수 없다 |

되돌리기 어려운 행동일수록 c_e가 크고 문턱이 높다. 비용 비율이 바뀌면 문턱은 코드에서 자동으로 다시 계산된다(`EndingCosts.thresholds()`).

### 3.2 출력 규칙 (앱 계층)

- **히스테리시스 0.10**: 단계는 문턱을 넘으면 오르고, 문턱 - 0.10 아래로 내려가야 내려온다. 빛이 오르내리며 깜빡이지 않게.
- **반대 신호가 오면 되돌림**: LR < 1 신호를 받으면 그 단계에서 올린 빛과 줄인 소리를 20초에 걸쳐 단계 시작 값으로 되돌린다. 단계가 내려가지 않더라도 되돌린다(시나리오 B, 12:26:49).
- **4초 침묵 규칙**: 마침 문장은 사용자의 마지막 움직임(신호) 뒤 4초 조용할 때만 말한다. 몸을 움직이는 도중에 말을 걸지 않는다 [가정].
- **한 번만 말한다**: 마침 문장은 세션당 1회. 반대 신호로 p가 떨어지면 다시 말하지 않고, 대신 빛만 되돌린다. 3분 뒤 다시 0.85를 넘으면 말 없이 끝 신호(종·나무 소리)만 낸다.
- **"마치기" 버튼**: 누르면 p = 1, 바로 돌아옴 단계. 이 시각이 개인화 관측값이다.
- **안전 사건이 언제나 먼저**: 2.5 하단 표의 사건은 p와 상관없이 처리한다.

## 4. 수치 예시: 정은 씨, 평일 21:40, 15분 기도, 40분 운전

b = (900 - 90) × exp(0.10 × ln(40/30)) = 833.6초 (13분 54초). σ = 0.18. 세션 시작 21:40:14.

- 신호가 없으면: 빛 13:54, 소리 15:17, 말 16:45. 의향(15:00)보다 1분 45초 늦다. 비대칭 비용이 의도한 "조금 늦게".
- 실제로는 정은 씨가 스스로 몸을 일으켜 14:40에 닫혔다. 의향보다 20초 일찍, 버튼 없이.
- 대조: 같은 세션 10:00에 등받이를 눕히면(반대 신호) p는 0.034에서 0.010으로, 말하는 시각은 16:45에서 16:48로 3초만 늦어진다. 이른 반대 신호는 거의 힘이 없다(6절 한계 1).

시나리오 B(점심 8분, 12분 운전, 무교): b = 355.9초. 신호 없음이면 빛 5:56, 소리 6:32, 말 7:09. 실제로는 6:40에 등받이를 눕혀(×0.3) p가 0.742에서 0.463으로 내려가 빛이 되돌아갔고, 7:25 시계 확인 터치(0.913)와 7:32 등받이 세움(0.987)으로 닫혔다.

## 5. 개인화: 기기 안의 공액 갱신

관측값 x = ln(실제 준비 시각) - ln b(맥락). 실제 준비 시각은 다음 중 가장 이른 것 [가정]:
1. "마치기" 버튼 누른 시각
2. 빛 올림 단계 이후 첫 준비 쪽 신호(LR > 1)의 시각
3. 그런 신호 없이 마침 문장 뒤 끝난 경우, 마침 문장 시각 (모델이 정한 시각이라 자기강화 편향이 있다. 6절 한계 2)

정규-역감마 갱신 (κ, α 는 관측 수):

```
m'  = (κ m + x) / (κ + 1)
κ'  = κ + 1
α'  = α + 1/2
β'  = β + κ (x - m)² / (2 (κ + 1))
```

중단된 세션(기어 이탈, 도어 열고 돌아오지 않음, 전화 뒤 마침)은 넣지 않는다. 엄밀히는 "적어도 이만큼은 머물렀다"는 우측 중도절단 관측이라 생존분석 우도로 넣을 수 있지만, 지금은 버린다(코드 주석의 shortcut).

초깃값 m=0, κ=2, α=3, β=0.0648 → E[σ²] = β/(α-1) = 0.18². κ=2는 "기본값을 세션 두 번만큼 믿는다"는 뜻 [가정].

예: 정은 씨가 15분을 고르지만 늘 10분(600초)에 준비된다면

| 세션 수 | m | 예측 σ | 새 기준 중앙값 | 빛 / 소리 / 말 (신호 없음) |
|---|---|---|---|---|
| 0 | 0.000 | 0.180 | 13:54 | 13:54 / 15:17 / 16:45 |
| 1 | -0.110 | 0.196 | 12:27 | 12:28 / 13:48 / 15:16 |
| 2 | -0.164 | 0.193 | 11:47 | 11:48 / 13:03 / 14:24 |
| 3 | -0.197 | 0.186 | 11:24 | 11:25 / 12:35 / 13:50 |
| 5 | -0.235 | 0.172 | 10:59 | 11:00 / 12:02 / 13:08 |

저장 위치: 기기 안(앱 전용 저장소)에만, 의향 종류(기도 / 조용히)별로 m, κ, α, β 네 숫자. 세션 내용·기도문·위치는 넣지 않는다 [근거: `SAFETY.md` 2절 원칙, `05_경험설계_재현.md` 3절 "데이터 최소"]. "기록 남기지 않기"를 켜면 갱신하지 않는다.

## 6. 평가 지표

| 상한 도달률 | 30분 상한으로 끝난 세션 비율 | 낮을수록 (잠들었을 가능성) | 2% 이하 |

평가는 기기 안에서 집계하고, 사용자가 켠 경우에만 집계 숫자(세션 내용 없음)를 보낸다.

## 7. 의사코드

```
on sessionStart(ctx):
    prior  = load(ctx.intent) or EndingPrior()
    policy = EndingPolicy(ctx, prior)
    saved  = getAll(HVAC, Seat, Light, Window, Door)

every 1 s while session && !paused:
    stage = policy.tick(elapsed)
    applyOutputs(stage)                    # 빛 +2%/분, 소리 페이드, 4초 침묵 후 1회 TTS

on vehicleSignal(s):
    if s is safetyEvent: quickRestore(saved); end(censored = true); return
    if s is pauseEvent:  paused = true; return          # 전화, 도어 열림
    if appMovedThisWithin(3 s): return                  # 앱이 스스로 바꾼 값은 신호 아님
    stage = policy.observe(s)
    if s.likelihoodRatio < 1: rewindOutputs(20 s)

on finishButton: policy.p = 1; readyAt = elapsed
on stage == CLOSING_WORDS and words spoken: startReturn(saved, 90 s)
on sessionEnd(not censored): save(prior.update(ctx, readyAt))
```

## 9. 한계와 다음 확인

1. **이른 반대 신호는 힘이 없다.** 흡수 상태 필터라 p가 작을 때 LR 0.3은 거의 아무것도 바꾸지 않는다. "오늘은 더 머물고 싶다"를 반영하려면 반대 신호가 μ 자체를 +0.1씩 미는 연장 규칙이 필요하다. 실사용에서 늦은 마침 지표가 나쁘면 넣는다.
2. **자기강화 편향.** 신호 없이 끝난 세션의 관측값을 모델이 정한 마침 시각으로 쓰면, 모델이 스스로를 학습한다. 첫 신호 시각을 우선 쓰는 이유이고, 그래도 남는 편향은 중도절단 우도로 바꿔 줄인다.
3. **신호 독립 가정.** 등받이 세움과 벨트 체결은 함께 일어나기 쉬워 우도비를 그냥 곱하면 과신한다. 30초 안의 LR 곱을 20으로 자르는 상한이 다음 후보다.
4. **LR 값은 전부 [가정]이다.** 첫 실사용 100세션의 로그(신호 시각, 버튼 시각)로 P(s|준비)/P(s|머묾)를 직접 센다.
5. [SDK 확인 필요] 등받이 위치 조회(실측에서 0만 반환), 브레이크 페달 속성, 벨트 체결 구독, 오디오 포커스 동작을 Pleos 에뮬레이터에서 각각 한 번씩 읽어 본다.
