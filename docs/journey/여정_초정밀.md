# 골방 사용 여정, 초 단위

작성 날짜: 2026-11-15 · 마침 판단: [마침_모델.md](마침_모델.md) · 재생용 키프레임: [`sim/journey/scenarios.json`](../../sim/journey/scenarios.json) (아래 표와 같은 값)

근거 파일 경로(`10_research/...`)는 팀 비공개 리서치 저장소 기준이고, 논문·문서 이름은 함께 적었다. 등장인물은 모두 가상이다. 표시: [근거]는 출처 있음, [가정]은 우리가 정한 값, [SDK 확인 필요]는 Pleos에서 아직 못 읽어 본 것.

**쓰는 순간은 둘이다.** 하나는 운전을 마치고 집에 들어가기 전이다(시나리오 A). 다른 하나는 일과 중 스스로 정한 기도 시간(점심, 오후 등)에 일을 잠시 놓고 회사 주차장에 세워 둔 차로 가서 기도하고 다시 일하러 돌아가는 때다. 첫 타깃은 두 경우 모두 매일 기도하는 한국 개신교 성인 운전자다. 시나리오 B는 같은 회사 주차장, 같은 점심 시간대를 "조용히 머물기" 팩(무교 사용자용, 확장 단계)으로 재생한 것이다. 개신교 사용자가 기도 시간에 차로 온 경우는 A의 기도 팩 흐름에 B의 낮 빛 값(문턱 25%, 머묾 20%)을 쓰고, 운전 없이 차에 타서 시작한다는 점이 다르다. 이 경우의 초 단위 표와 재생 데이터는 아직 만들지 않았다. 앱은 시동을 걸거나 차 밖에 있는 사람을 부르지 못한다. 기도 시간 알림은 휴대폰에서만 할 수 있고 [가정], 차는 사람이 타서 P단, 착좌, 문 닫힘이 확인된 뒤에 묻는다. 시동을 켜지 않은 차에서 조명과 공조가 얼마나 바뀌는지는 [SDK 확인 필요].

**공통 표기**
- 레버 순서: 공조 ℃ · 풍량(1~8) · 내/외기 / 열선(-3~3) / 등받이(0~1, 클수록 세움) / 앰비언트 밝기%·색·전이ms / 창문%(0 닫힘) / 잠금 / 사이드미러.
- 시작값(모든 시나리오): 22℃ · 3 · 외기 / 0 / 0.55 / 30% #FFFFFF / 0% / 잠김 / 펼침. 에뮬레이터 실측 뒤 정리 상태와 같다 [근거: `prj-2026-hyundai-codeyourapp/10_research/android-pleos/2026-11-15_골방모드_차량제어_가능성.md` 실측 절].
- 소리 dB은 사용자가 정한 앱 기준 음량 대비 상대값이다. 시스템 볼륨 SDK는 없다 [근거: 같은 문서 "소리(재생)"].
- 등받이는 위치 지정 set이 없고 앞/뒤 이동과 정지만 있다. 그래서 0.55→0.45 같은 값은 "이동 시간"으로 만든다. P단에서만 된다(D단 50001) [근거: 같은 문서].
- 사이드미러 접힘은 SDK로 못 바꾼다(SideMirror 도메인은 열선만). 표에는 차가 스스로 하는 동작만 적는다 [근거: `pleos-platform-map/01_Pleos_API_카탈로그.md` 2.2].
- 근거 파일 약칭: **05** = `10_research/domain/2026-11-15_차안의식_리서치/D8_경험설계_재현/05_경험설계_재현.md`, **02** = `D3_심리_생리_근거/02_심리생리_근거.md`, **01** = `D1_종교와_의례/01_의식행위_종교별.md`, **D7** = `D7_우수UX_사례/00_사례와_교집합.md`, **D12** = `D12_글로벌타깃/00_타깃결정_한장.md`, **실측** = `android-pleos/2026-11-15_골방모드_차량제어_가능성.md`, **카탈로그** = `01_Pleos_API_카탈로그.md`.
