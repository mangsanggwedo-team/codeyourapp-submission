**확인 등급**
- **직접**: 이번에 페이지를 열어 본문을 읽었다.
- **검색**: 검색 결과 요약으로만 확인했다. 화면 이미지 자체는 보지 못했으므로 "배울 것"은 글로 확인된 범위에 한정한다.
- **팀**: 팀 리서치(D7, D14, 아트 디렉션)에 이미 정리된 출처를 다시 가리킨다.

Pinterest는 로그인 없이 공개 검색 결과에 나온 주제 페이지만 적었다. 로그인은 하지 않았다.

적용한 스킬: `ui-ux-pro-max`(접근성 4.5:1, 터치 크기, 모션 타이밍 우선순위), `frontend-design`(한 군데에만 대담함, 기본값 회피, 문구도 디자인), `taste-skill`(한 화면 한 가지, 설명 캡션 금지, 보라 남용 금지). 세 스킬의 웹 랜딩 전용 규칙(히어로, 섹션 게이트)은 차량 앱에 맞지 않아 쓰지 않았다.

## 5. 묶어서 본 결론

1. **가장 가까운 선례(Lincoln Rejuvenate, BMW Relax, Mercedes 프로그램)는 모두 화면을 그림으로 채운다.** 룸19는 정반대로 화면을 비운다. 여기가 차별점이다. 밤에 화면이 가장 센 광원이라는 조명 결정과도 맞는다.
2. **호흡 화면의 정답은 이미 있다.** 형태 하나가 커지고 작아진다. 우리는 색 번짐 없이 선 하나짜리 원으로 줄이고, 말은 첫 번만 한다.
3. **기도 앱이 욕먹는 지점(기록, 목표, 결제 권유)은 화면에 아예 자리를 주지 않는다.** 차량판에는 홈, 목록, 탭이 없다.
4. **Pleos 가이드의 수치(5mm, 3mm, 4.5:1, 3줄, 0.25초)는 그대로 지킨다.** 단 머묾 중 "마치기"는 일부러 낮은 밝기라 대비 예외다. 화면을 한 번 두드리면 정상 대비로 돌아오게 해서 보완한다(컨셉 문서 접근성 절).
5. **확인 못 한 것:** Pleos 상태 바, GNB, 반쪽 창의 정확한 치수와 버튼 치수는 그림 안에만 있어 읽지 못했다. 시안의 상단 띠와 여백은 가정이다. Pinterest, Dribbble, Behance, Mobbin, Awwwards 항목은 검색 요약만 보았고 화면 그림을 직접 보지 않았다.
